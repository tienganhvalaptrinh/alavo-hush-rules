# alavo-hush-rules

Public rule sets for the Alavo Hush Android app. Hush blocks the feed and web of social networks while keeping their chat apps working. This repository says, for each service, which domains to block or allow and for which apps.

The app ships with a copy of these rules and downloads newer ones from this repository when it can. When a service changes its domains, a pull request here fixes it for everyone without a new app release.

## Key terms

- **Domain**: the name of a site or server, such as `facebook.com`. A rule for `facebook.com` also covers every subdomain, such as `m.facebook.com`.
- **Package name**: the unique id of an Android app, such as `com.facebook.orca` for Messenger. It is how a rule refers to one specific app.
- **Service**: one social network or messenger, such as Facebook. One file in `services/` per service.
- **Component**: one part of a service that the user can switch on or off. Facebook has four: the app, the website, Facebook pages opened inside Messenger, and Messenger itself.
- **Rule**: one line that says `block` or `allow` for one domain, for either all apps or a list of apps (its scope).
- **Index**: `index.json`, the list of every service file with its version and a hash. The app downloads it first to learn what changed.
- **Signature**: `index.json.sig`, a proof that the index was published by the maintainers. It is made at publish time and is not stored in git.

## How a rule is written

A service file holds components, and each component holds rules. This is the Facebook web component, trimmed:

```json
{
  "id": "web",
  "kind": "web",
  "status": "stable",
  "enabledByDefault": true,
  "rules": [
    { "domain": "facebook.com", "action": "block", "scope": "all" }
  ]
}
```

And the Messenger chat component, which keeps Messenger working:

```json
{
  "id": "messenger",
  "kind": "chat",
  "packages": ["com.facebook.orca"],
  "rules": [
    { "domain": "*", "action": "allow", "scope": ["com.facebook.orca"] }
  ]
}
```

`"*"` means every domain and is only allowed when the scope lists specific apps. The full format is in `schema/service.schema.json`.

The four kinds of component:

- `app`: blocks everything for the listed apps. It only contains `"*"` block rules.
- `web`: blocks website domains for all apps. It lists no packages.
- `webview`: blocks website domains only for the listed apps, to catch web pages opened inside a chat app.
- `chat`: keeps the listed apps working. It only contains `allow` rules.

A component with `status` other than `stable` that contains block rules must have `enabledByDefault` set to `false`, so unmeasured rules never ship switched on.

## Which rule wins

When several rules match the same question ("may app A look up domain D?"), the app picks one in this order:

1. A rule scoped to app A beats a rule scoped to `all`.
2. Among rules of the same scope kind, the one with the more specific domain wins. `graph.facebook.com` beats `facebook.com`, and anything beats `*`.
3. If they are still tied, `allow` beats `block`.
4. The user's own rules in the app beat every rule from this repository.

Example. Rules: block `facebook.com` for all, allow `*` for Messenger. Chrome asks for `www.facebook.com`: only the first rule matches, so it is blocked. Messenger asks for `graph.facebook.com`: both match, the Messenger rule is scoped to the app so it wins, and the lookup is allowed. A rule that blocks `www.facebook.com` for Messenger only would still beat the `*` allow, because its domain is more specific within the same scope kind.

## What is in this repository

```
services/                    one JSON file per service, written by hand
notes/                       what was measured on a real device, per service
schema/                      JSON Schema files that define every format
scripts/                     validate, build the index, sign, publish
keys/                        the public half of the signing key
protected-domains.json       domains that no rule may block
index.json                   generated by "npm run build", do not edit
.github/workflows/           the checks and the publishing
```

## Safety rules

- **Protected domains.** No rule may block a domain listed in `protected-domains.json`, or one of its subdomains or parents. It holds the domains the phone and this very download depend on, such as `github.io`, `google.com` and `apple.com`.
- **Signed publishing.** The app only trusts an index whose signature verifies against the public key in `keys/`. See `keys/README.md`.
- **Hashes.** `index.json` lists the SHA-256 of every service file, so a tampered service file is rejected even if the index is real.
- **Unmeasured rules stay off.** Anything that could break chat ships disabled until it has been measured on a device.

## Where the app downloads from

After GitHub Pages is switched on (repository settings, Pages, Source: GitHub Actions), every push to `main` publishes the rules to:

```
https://tienganhvalaptrinh.github.io/alavo-hush-rules/index.json
https://tienganhvalaptrinh.github.io/alavo-hush-rules/index.json.sig
https://tienganhvalaptrinh.github.io/alavo-hush-rules/services/<id>.json
```

The app asks only for these fixed files. It sends no user id and no list of installed apps. GitHub still sees the IP address of the request, like any file download.

## Contributing

You need Node.js 20 or newer.

```
npm install
npm run build     # validates and regenerates index.json
npm run check     # the same, but fails instead of writing; this is what CI runs
```

See [CONTRIBUTING.md](CONTRIBUTING.md) for how to add a service or change a rule.

## Status

The structure and the checks exist. No service has been measured on a device yet, so every chat component is `unmeasured` and the Messenger web view rules are off by default. See `notes/`.
